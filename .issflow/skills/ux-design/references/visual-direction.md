# Distinctive visual direction, with usable previews

A catalogue is inspiration, never the finished identity. Do not force every
project into the same SaaS shell, gradient hero, pill badges, bento cards, oversized
headline or decorative dashboard. These patterns are not banned: each must earn
its place through the content, task and brand. Do not promise a design is unique
across the internet or that no one can identify it as AI-generated.

## Brief before pixels
Capture audience, business context, brand personality, desired feeling, real
content, imagery/asset rights, existing equity and examples the owner likes or
rejects. Record why each reference fits rather than copying it. If the owner asks
for minimal luxury, interpret restraint, confident hierarchy, precise typography,
careful spacing, material/imagery quality and limited accents; do not automatically
apply gold on black, tiny low-contrast type or unusably sparse controls.

## Compare meaningful alternatives
Create 2–3 distinct directions unless one is already selected. Compare the SAME
representative task and realistic content, desktop and narrow screen, plus one
important non-happy state. Vary composition, typography, density, imagery and
interaction treatment, not only palette. Include a restrained minimal-luxury
option when appropriate to the brief, not as the default for every product.
Explain audience fit, usability tradeoffs, implementation cost and accessibility.
Existing products should include an evolution option that preserves recognizable
navigation and contracts, with a separate bolder alternative if requested.

## Show real previews
Use the existing picker as comparison chrome; attach/link actual renderable HTML
or project-native prototype previews and inspected screenshots. Swatches and
marketing adjectives alone do not count as previews. Never claim to have rendered
or browser-checked a preview without doing it. If rendering is unavailable, label
it unverified and provide the artifact plus the exact missing check.
Use local/self-contained assets when possible. No unexpected third-party font,
image or tracking requests. Label placeholder content and asset licensing gaps.
Keyboard controls, readable type, visible focus and responsive behavior apply to
prototypes too. A static preview is not production functionality.

## Lock, translate, maintain
Owner chooses a direction before production restyling. Record decision, rationale,
preview locations, typography, semantic tokens, component and layout principles,
anti-patterns and responsive rules in DIRECTION.md. Reuse the component system but
adapt composition to the job. The generic wireframe is a starting scaffold, not a
mandatory top-bar/sidebar/card aesthetic. Approved project wireframes own the frame.
Run a side-by-side fidelity review after implementation. Intentional departures
need a recorded decision, not a silent drift or rigid adherence to a bad default.
