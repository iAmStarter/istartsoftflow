# PLAN-0003 — ESM-compatible installer hooks

> Revision: 1
> Status: PENDING
> Repository: iAmStarter/istartsoftflow
> Base: main
> Target release: create-issflow@1.10.1

## Goal
Fix the confirmed CommonJS/ESM runtime incompatibility when iStartSoftFlow hooks are installed in projects whose package.json declares `"type": "module"`. Preserve existing project customizations and behavior.

## Verified root cause
The installed hook scripts `.issflow/hooks/approval-policy.js`, `plan-gate.js`, and `verify-approval.js` use `require` / `module.exports` but are placed under the consuming project's package scope. In a project with `"type": "module"`, Node treats `.js` files as ESM and throws `require is not defined`.

## Approach
1. Use an explicit CommonJS boundary for the portable hook scripts (prefer `.cjs`), update all internal imports and all references in the kit, templates, generated adapters, CLI guidance, CI, and tests.
2. Audit other shipped Node scripts for the same package-scope hazard and include only directly related changes. Preserve the kit's source-of-truth generation process.
3. Keep compatibility for existing installs: do not destructively overwrite customized `.js` hooks; provide migration instructions and safe conflict handling for `.issflow-new`.
4. Add regression tests in temporary CommonJS and ESM consumer projects: hook denial/approval, verifier execution, installer dry-run/install, and generated template contents.
5. Exclude `__pycache__/`, `*.pyc`, and other generated bytecode from the portable kit and npm package if they are included, with tests.
6. Run Node tests, build reproducibility, `npm pack --dry-run`, and packed-package smoke tests.
7. Prepare a patch version `1.10.1` and concise changelog; open a PR for owner review.

## Acceptance criteria
- No `require is not defined` errors in ESM projects.
- Existing CommonJS projects remain supported.
- Pending plans deny protected edits and approved plan scope checks still work.
- Installer remains non-destructive and handles conflicts transparently.
- Generated template matches source after rebuild.
- Tests pass and npm package contains the correct portable scripts, not bytecode cache.
- PR is ready for review, but no merge, tag, npm publish, or TwinFlow changes occur automatically.
