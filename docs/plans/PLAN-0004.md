## Goal
Add host-aware advisory model routing for Codex, Claude Code, and Cursor, with automatic switching only where a verified host-native mechanism is available. Preserve tool-agnostic operation and existing plan-scoped approvals, tests, hooks, human merge and release gates.

## Scope
1. Define capability tiers (economy, balanced, advanced) and risk-aware routing defaults per agent.
2. Use only verified host model identifiers and supported effort levels. Never infer executable IDs from UI labels.
3. Default to advisory/inherit. Automatic switching requires explicit host support and confirmation; unsupported hosts fall back safely.
4. Add unit tests and documentation; integrate with installer templates only through the existing build process.
5. Validate against the approval policy, existing workflow tests, generated installer template, and packaging checks.

## Acceptance criteria
1. Unverified model IDs or effort levels never result in an automatic switch.
2. Advisory routing never modifies host state.
3. Automatic mode switches only through a supported host-native interface and reports success only after verified confirmation.
4. High-risk security and architecture tasks escalate tiers without bypassing any approval or release gate.
5. Unsupported provider/host capability returns an explicit safe fallback.
6. Existing approval tests and routing tests pass.
7. Generated installer template is reproducible from portable kit source.
8. Existing PR remains reviewable; no merge, production deployment, tag or npm publish.

## Risks and mitigations
- Host API limitations: report advisory-only rather than claiming automatic switching.
- Model availability drift: keep mappings configurable and require verified IDs.
- Approval bypass: do not alter the approval verifier, its allowed-path policy, or human sign-off requirements.
- Package drift: regenerate and validate templates before declaring ready.
