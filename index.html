whyทำไม

Mandatory steps live in hooks. Thinking lives in agents.ขั้นตอนบังคับอยู่ใน hooks — การคิดอยู่ใน agents

It pins a process, not a stack. Deterministic rituals (read the issue log, snapshot before compaction) run as lifecycle hooks so they can't be skipped; the reasoning runs in fresh-context subagents that return only summaries. Declare your stack once in docs/OVERVIEW.md — every rule references your stack and hardcodes none. มันยึด กระบวนการ ไม่ใช่ stack. ขั้นตอนที่ต้องทำแน่ๆ (อ่าน issue log, snapshot ก่อน compact) รันเป็น lifecycle hook จึงข้ามไม่ได้; ส่วนการคิดรันใน subagent ที่ context สดและส่งกลับแค่สรุป. ประกาศ stack ครั้งเดียวใน docs/OVERVIEW.md — ทุกกฎอ้างถึง stack ของคุณ ไม่ฮาร์ดโค้ดอะไรเลย

UX guardrailการ์ดราว UX

The ux-design cookbookcookbook

Generated UI is validated against a frame so it can't drift. The skill bundles a cookbook (design tokens · 8‑pt grid · WCAG 2.1 AA · state matrix · breakpoints · i18n) and a canonical wireframe baseline under references/ — loaded only when you touch UI. A frontend phase can't close until the check passes. UI ที่สร้างจะถูกตรวจกับ "กรอบ" ไม่ให้หลุดดีไซน์ สกิลนี้รวม cookbook (design token · กริด 8‑pt · WCAG 2.1 AA · state matrix · breakpoint · i18n) และ wireframe ต้นแบบ ไว้ใน references/ — โหลดเฉพาะตอนทำ UI และ phase ฝั่งหน้าบ้านปิดไม่ได้จนกว่าจะผ่านการตรวจ

🎨 Tokensโทเคน

No raw hex/px — named tokens, 8-pt spacing scale, fixed type ramp.ห้าม hex/px ดิบ — ใช้ token มีชื่อ, สเกลระยะ 8-pt, type ramp ตายตัว

♿ Accessibilityการเข้าถึง

Contrast ≥ 4.5:1, keyboard-reachable, semantic HTML, 44×44 hit areas.คอนทราสต์ ≥ 4.5:1, ใช้คีย์บอร์ดได้, semantic HTML, พื้นที่กด 44×44

📐 Wireframe-firstเริ่มที่ wireframe

Every screen maps to a low-fidelity baseline before pixels exist. Drift = defect.ทุกหน้าจอแมปกับต้นแบบ low-fidelity ก่อนมีพิกเซล — หลุดกรอบ = ข้อบกพร่อง

workflow best practicesแนวปฏิบัติที่ดี

How to drive it wellขับเคลื่อนให้ดีต้องทำยังไง

Distilled from how teams run coding agents (sourced notes in docs/research/). The kit enforces most of these.กลั่นจากวิธีที่ทีมจริงใช้ coding agent (บันทึกพร้อมแหล่งที่มาใน docs/research/) — kit บังคับใช้ส่วนใหญ่ให้แล้ว

  • Context hygieneสุขอนามัย context — fresh context per task; /synthesize → /clear between phases; delegate noisy work to subagents.context สดต่อหนึ่งงาน; /synthesize → /clear ระหว่าง phase; โยนงานรกๆ ให้ subagent
  • Spec-firstเริ่มที่ spec — write acceptance criteria before code; a human approves the plan; thin vertical slices, not layers.เขียนเกณฑ์ยอมรับก่อนโค้ด; คนอนุมัติแผนก่อน; ตัดเป็น vertical slice บางๆ ไม่ใช่แบ่งเป็นเลเยอร์
  • TDD, blindTDD แบบ blind — tests written from the spec without seeing the code, RED-first. Never edit a test to make it pass.เขียนเทสต์จาก spec โดยไม่เห็นโค้ด, RED ก่อน — ห้ามแก้เทสต์เพื่อให้ผ่าน
  • Debug disciplineวินัยการดีบัก — cap attempts at 3; grep the issue log first; log every fix with its root cause.จำกัด 3 ครั้ง; grep issue log ก่อน; บันทึกทุกการแก้พร้อม root cause
  • Review the diffรีวิว diff — never trust "it works"; small changes; feature branch, never the default branch.อย่าเชื่อคำว่า "มันรันได้"; เปลี่ยนทีละนิด; ทำบน feature branch ไม่ใช่ branch หลัก
  • Securityความปลอดภัย — least-privilege tools; humans approve destructive/outbound actions; secrets in env, never in prompts.ให้สิทธิ์เครื่องมือน้อยที่สุด; คนอนุมัติงานที่ลบ/ส่งออก; เก็บ secret ใน env ไม่ใส่ใน prompt
