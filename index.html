whyทำไม

Mandatory steps live in hooks. Thinking lives in agents.ขั้นตอนบังคับอยู่ใน hooks — การคิดอยู่ใน agents

It pins a process, not a stack. Deterministic rituals (read the issue log, snapshot before compaction) run as lifecycle hooks so they can't be skipped; the reasoning runs in fresh-context subagents that return only summaries. Declare your stack once in docs/OVERVIEW.md — every rule references your stack and hardcodes none. มันยึด กระบวนการ ไม่ใช่ stack. ขั้นตอนที่ต้องทำแน่ๆ (อ่าน issue log, snapshot ก่อน compact) รันเป็น lifecycle hook จึงข้ามไม่ได้; ส่วนการคิดรันใน subagent ที่ context สดและส่งกลับแค่สรุป. ประกาศ stack ครั้งเดียวใน docs/OVERVIEW.md — ทุกกฎอ้างถึง stack ของคุณ ไม่ฮาร์ดโค้ดอะไรเลย

Hook-enforcedบังคับด้วย hook

SessionStart / PreCompact / SubagentStop inject live state and snapshot recovery — automatically, every session.SessionStart / PreCompact / SubagentStop ฉีดสถานะสดและ snapshot กู้คืน — อัตโนมัติทุก session

Agent orchestrationออร์เคสเตรต agent

An orchestrator routes work to 7 specialist subagents (plan, research, implement, test, debug, e2e, synthesize) that isolate the noise.ตัวออร์เคสเตรตกระจายงานไป 7 subagent เฉพาะทาง (plan, research, implement, test, debug, e2e, synthesize) ที่แยก noise ออกไป

Token-lean by designประหยัด token ตั้งแต่ดีไซน์

The methodology & skills load on demand; only live state + open issues are paid each session. Cost doesn't grow with history.methodology และ skill โหลดเมื่อใช้; จ่ายเฉพาะสถานะสด + issue ที่เปิดอยู่ ต่อ session ค่าใช้จ่ายไม่โตตามประวัติ

getting startedเริ่มต้นยังไง

The flow, step by stepขั้นตอนการทำงานทีละสเต็ป

Six commands, end to end — each one bundles several lifecycle stages (the full flow is 9 stages). Every step writes a durable artifact and is logged.6 คำสั่ง ตั้งแต่ต้นจนจบ — แต่ละคำสั่งรวมหลาย stage ไว้ในตัว (lifecycle เต็มมี 9 stage) ทุกสเต็ปเขียนไฟล์เก็บไว้และมี log ครบ

  1. 1

    Installติดตั้ง

    npx create-issflow --tool=claude

    Scaffolds .claude/ into your project (non-destructive). Open it in your AI tool — the SessionStart hook fires automatically.วาง .claude/ ลงในโปรเจกต์ (ไม่ทับไฟล์เดิม) เปิดในเครื่องมือ AI ของคุณ — hook ทำงานอัตโนมัติ

  2. 2

    Discover & planค้นหาความต้องการ + วางแผน

    /overview

    Tell it your idea. It grills you (2 passes, to convergence — 5-whys depth on shallow answers), runs design-research, picks the stack & architecture, and writes OVERVIEW.md + PLAN.md. Planning is interactive — asking is good here.เล่าไอเดียให้ฟัง มันจะ ซักคุณ (2 รอบ จนตกผลึก — เจาะลึกแบบ 5-whys ถ้าคำตอบยังตื้น) ทำ design-research เลือก stack/architecture แล้วเขียน OVERVIEW.md + PLAN.md ขั้นวางแผนถามได้เต็มที่

    inside · discover → PRD → stack & architecture → grill ×2 → plan

  3. 3

    Proposal & priceเสนอราคา

    /propose

    Turns scope + phases into an effort + cost estimate (range + assumptions) and a timeline. You sign off before any build.แปลง scope + phases เป็นประเมินแรง+ราคา (เป็นช่วง + ระบุสมมุติฐาน) และไทม์ไลน์ คุณเซ็นอนุมัติก่อนเริ่มสร้าง

  4. 4

    Build, phase by phaseสร้างทีละ phase

    /phase

    The AUTO dev loop: implement → blind tests → UX + security gates → close. Follows the plan without stopping to ask; logs every decision, issue, and fix.AUTO dev loop: implement → blind test → เกต UX + security → ปิด ทำตามแผนไม่หยุดถาม และ log ทุก decision/ปัญหา/การแก้

    inside · implement → blind tests → UX + security gates → deploy (final phase) → close

  5. 5

    Change mid-wayเปลี่ยนกลางทาง

    /change-request "…"

    Assesses impact, re-estimates the cost delta fairly, logs a change order, gets sign-off, then replans — scope/cost never change silently.ประเมินผลกระทบ คิดราคาส่วนต่างอย่างสมเหตุสมผล บันทึก change order ขออนุมัติ แล้ว replan — scope/ราคาไม่เปลี่ยนเงียบๆ

  6. 6

    Close outปิดโปรเจกต์

    /synthesize

    Final pass writes a project summary: what was built, key decisions, every change order, and the final cost vs the original estimate.รอบสุดท้ายเขียนสรุปโปรเจกต์: สร้างอะไรไปบ้าง decision สำคัญ change order ทุกอัน และราคาสุดท้ายเทียบกับที่ประเมินไว้

UX guardrailการ์ดราว UX

The ux-design cookbookcookbook

Generated UI is validated against a frame so it can't drift. The skill bundles a cookbook (design tokens · 8‑pt grid · WCAG 2.1 AA · state matrix · breakpoints · i18n) and a canonical wireframe baseline under references/ — loaded only when you touch UI. A frontend phase can't close until the check passes. UI ที่สร้างจะถูกตรวจกับ "กรอบ" ไม่ให้หลุดดีไซน์ สกิลนี้รวม cookbook (design token · กริด 8‑pt · WCAG 2.1 AA · state matrix · breakpoint · i18n) และ wireframe ต้นแบบ ไว้ใน references/ — โหลดเฉพาะตอนทำ UI และ phase ฝั่งหน้าบ้านปิดไม่ได้จนกว่าจะผ่านการตรวจ

Tokensโทเคน

No raw hex/px — named tokens, 8-pt spacing scale, fixed type ramp.ห้าม hex/px ดิบ — ใช้ token มีชื่อ, สเกลระยะ 8-pt, type ramp ตายตัว

Accessibilityการเข้าถึง

Contrast ≥ 4.5:1, keyboard-reachable, semantic HTML, 44×44 hit areas.คอนทราสต์ ≥ 4.5:1, ใช้คีย์บอร์ดได้, semantic HTML, พื้นที่กด 44×44

Wireframe-firstเริ่มที่ wireframe

Every screen maps to a low-fidelity baseline before pixels exist. Drift = defect.ทุกหน้าจอแมปกับต้นแบบ low-fidelity ก่อนมีพิกเซล — หลุดกรอบ = ข้อบกพร่อง

Secure SDLCSecure SDLC

Security at every stage, not bolted onความปลอดภัยทุก stage ไม่ใช่แปะทีหลัง

The security skill weaves a Secure SDLC through the loop: threat-model at design, secure coding while building, SAST/SCA/secrets at every phase close, a pentest gate + security review before deploy, and vulnerability management after. Grounded in OWASP Top 10 (2025), ASVS 5.0, WSTG, ISO/IEC 27001 & 25010, and SLSA. สกิล security ร้อย Secure SDLC ผ่านทั้งลูป: threat-model ตอนออกแบบ, secure coding ตอนเขียน, SAST/SCA/secrets ทุกครั้งที่ปิด phase, pentest gate + security review ก่อน deploy, และ vulnerability management หลังจากนั้น อิง OWASP Top 10 (2025), ASVS 5.0, WSTG, ISO/IEC 27001 และ 25010, SLSA

workflow best practicesแนวปฏิบัติที่ดี

How to drive it wellขับเคลื่อนให้ดีต้องทำยังไง

Distilled from how teams run coding agents (sourced notes in docs/research/). The kit enforces most of these.กลั่นจากวิธีที่ทีมจริงใช้ coding agent (บันทึกพร้อมแหล่งที่มาใน docs/research/) — kit บังคับใช้ส่วนใหญ่ให้แล้ว

  • Context hygieneสุขอนามัย context — fresh context per task; /synthesize → /clear between phases; delegate noisy work to subagents.context สดต่อหนึ่งงาน; /synthesize → /clear ระหว่าง phase; โยนงานรกๆ ให้ subagent
  • Spec-firstเริ่มที่ spec — write acceptance criteria before code; a human approves the plan; thin vertical slices, not layers.เขียนเกณฑ์ยอมรับก่อนโค้ด; คนอนุมัติแผนก่อน; ตัดเป็น vertical slice บางๆ ไม่ใช่แบ่งเป็นเลเยอร์
  • TDD, blindTDD แบบ blind — tests written from the spec without seeing the code, RED-first. Never edit a test to make it pass.เขียนเทสต์จาก spec โดยไม่เห็นโค้ด, RED ก่อน — ห้ามแก้เทสต์เพื่อให้ผ่าน
  • Debug disciplineวินัยการดีบัก — cap attempts at 3; grep the issue log first; log every fix with its root cause.จำกัด 3 ครั้ง; grep issue log ก่อน; บันทึกทุกการแก้พร้อม root cause
  • Review the diffรีวิว diff — never trust "it works"; small changes; feature branch, never the default branch.อย่าเชื่อคำว่า "มันรันได้"; เปลี่ยนทีละนิด; ทำบน feature branch ไม่ใช่ branch หลัก
  • Securityความปลอดภัย — least-privilege tools; humans approve destructive/outbound actions; secrets in env, never in prompts.ให้สิทธิ์เครื่องมือน้อยที่สุด; คนอนุมัติงานที่ลบ/ส่งออก; เก็บ secret ใน env ไม่ใส่ใน prompt
