How to use iStartSoftFlowวิธีใช้งาน iStartSoftFlow

No jargon without an explanation. Ten minutes here and you can run the whole kit. ไม่มีศัพท์ยากที่ไม่อธิบาย อ่านสิบนาทีก็ใช้งานได้ทั้งชุด

What is this, in plain words?นี่คืออะไร (อธิบายแบบบ้าน ๆ)

When you ask an AI to write code, it usually "guesses and goes" — fast, but things break, it loops on fixes, and your AI bill grows. ปกติเวลาให้ AI เขียนโค้ด มันมักจะ "เดาแล้วลุย" — ทำเร็วแต่พังบ่อย วนแก้ไปเรื่อย เปลืองค่า AI ขึ้นเรื่อย ๆ

iStartSoftFlow is a rulebook + a team of helpers that makes the AI work like a professional team: understand first → plan → get your approval → build one slice at a time → test everything → deliver with a test sheet for you. iStartSoftFlow คือชุดกฎ + ทีมผู้ช่วย ที่จับ AI มาทำงานแบบมืออาชีพ: ถามให้เข้าใจก่อน → วางแผน → ให้คุณอนุมัติ → ลงมือทำทีละส่วน → เทสต์ทุกครั้ง → ส่งงานพร้อมใบทดสอบ

Think of it as upgrading from "an intern who guesses" to "a team with a project manager" — and the important rules are enforced by small programs (hooks) the AI cannot skip, not by politely asking it. Free (MIT); you pay only for the AI you already use. เปรียบง่าย ๆ: เหมือนเปลี่ยนจาก "เด็กฝึกงานที่เดางานเก่ง" เป็น "ทีมที่มีหัวหน้าโปรเจกต์คุมงาน" — โดยกฎสำคัญถูกบังคับด้วยโปรแกรมเล็ก ๆ (เรียกว่า hook) ที่ AI แอบข้ามไม่ได้ ไม่ใช่แค่ขอร้องปากเปล่า ของฟรี (MIT) จ่ายแค่ค่า AI ที่ใช้อยู่แล้ว

What you need firstต้องมีอะไรก่อนเริ่ม

  • Node.js 18+ — check with node -v (get it at nodejs.org)Node.js เวอร์ชัน 18 ขึ้นไป — ตรวจด้วย node -v (ยังไม่มีโหลดที่ nodejs.org)
  • Claude Code — install with npm install -g @anthropic-ai/claude-code, log in when it asks. (Codex / Cursor / Gemini / Aider also work; Claude Code gets the most features.)Claude Code — ติดตั้งด้วย npm install -g @anthropic-ai/claude-code แล้วล็อกอินตามที่มันถาม (ใช้ Codex / Cursor / Gemini / Aider ก็ได้ แต่ Claude Code ได้ครบสุด)
  • A project folder — brand new or an existing codebase, both fine.โฟลเดอร์โปรเจกต์ — งานใหม่ถอดด้ามหรือของเดิมที่มีโค้ดแล้วก็ได้

Install (1 minute)ติดตั้ง (1 นาที)

In your project folder:เปิด Terminal เข้าโฟลเดอร์โปรเจกต์ แล้วพิมพ์:

$ npx create-issflow

Pick your AI tool (usually claude). It never overwrites your files — conflicts are written next to yours. Re-run any time to update. Then open your AI tool there: เลือกเครื่องมือ AI ของคุณ (ส่วนใหญ่คือ claude) มันไม่ทับไฟล์เดิมเด็ดขาด — ถ้าชนกันจะเขียนไฟล์ใหม่แยกไว้ให้ดู ติดตั้งซ้ำเพื่ออัปเดตได้ตลอด จากนั้นเปิดเครื่องมือ AI ในโฟลเดอร์นั้น:

$ claude

Pick your situationใช้ยังไง — เลือกตามสถานการณ์

1 · Starting a brand-new project → 1 · เริ่มโปรเจกต์ใหม่ทั้งอัน → /overview

It interviews you like a good PM: what are we building, for whom, what constraints. Answer honestly — "I don't know" is fine (it will research). Then it writes a plan and stops: read and approve it first. This is a real lock — while the plan is unapproved, the AI physically cannot edit source files. After approval, build slice by slice with /phase: tests written first → code until green → security check → close. Repeat until done. มันจะสัมภาษณ์คุณเหมือน PM มืออาชีพ: สร้างอะไร ให้ใครใช้ ติดข้อจำกัดอะไร ตอบตามจริง ไม่รู้บอกไม่รู้ได้ (เดี๋ยวมันไปหาข้อมูลเอง) จบแล้วมันเขียนแผนงานมาให้ — อ่านแล้วอนุมัติก่อน นี่คือตัวล็อกจริง ๆ: แผนยังไม่อนุมัติ AI แก้ไฟล์โค้ดไม่ได้เลย อนุมัติแล้วสั่ง /phase สร้างทีละช่วง: เขียนเทสต์ก่อน → เขียนโค้ดจนผ่าน → ตรวจความปลอดภัย → ปิดงาน วนจนจบแผน

2 · Adding a feature to an existing product → 2 · เพิ่มฟีเจอร์ให้ระบบที่มีอยู่ → /feature

  1. Get the work-order form: /feature new my-feature → creates docs/features/my-feature/FEATURE.md ขอฟอร์มใบสั่งงาน: /feature new ชื่อฟีเจอร์ → ได้ไฟล์ docs/features/ชื่อ/FEATURE.md
  2. Fill it in normal human language: what you want, why, what it must do, what is NOT included. Then change the top line Approval: PENDING → Approval: APPROVED yourname date — that's your signature. เขียนอธิบายด้วยภาษาคนธรรมดา: อยากได้อะไร ทำไม ต้องทำอะไรได้ อะไรที่ไม่เอา แล้วแก้บรรทัดบน Approval: PENDING เป็น Approval: APPROVED ชื่อคุณ วันที่ — นี่คือลายเซ็นของคุณ
  3. Release the work: /feature — then walk away. It attacks the spec for holes → mini-plans → writes tests first, then code → hardens with adversarial review → produces a human test sheet → delivers a branch. ปล่อยงาน: /feature — แล้วไปทำอย่างอื่นได้เลย มันจะรุมตรวจใบสั่งงานหาช่องโหว่ → วางแผนย่อย → เขียนเทสต์ก่อนค่อยเขียนโค้ด → ตรวจซ้ำแบบโหด ๆ → ทำใบทดสอบสำหรับมนุษย์ → ส่งงานกลับมาเป็น branch
  4. Your only job: open the generated TEST-PLAN.md, click through the scenarios, merge when everything passes. งานของคุณมีแค่นี้: เปิด TEST-PLAN.md ที่มันทำให้ กดทดสอบตามทีละข้อ ผ่านหมดก็รวมงาน (merge) จบ

3 · A tiny fix → 3 · แก้งานเล็ก ๆ → /quick

/quick describe what to change — it repeats its understanding back and waits for your confirm, then makes the smallest change that works, with a regression check so nothing else breaks. /quick อธิบายสิ่งที่อยากแก้ — มันจะทวนความเข้าใจให้ฟังก่อน รอคุณยืนยัน แล้วค่อยแก้ให้เล็กที่สุดเท่าที่งานสำเร็จ พร้อมรันเทสต์กันของเดิมพัง

All commands, translated to humanคำสั่งทั้งหมด แปลเป็นภาษาคน

You only need three to be productive: /overview to start · /feature to add · /quick to fix. จำแค่ 3 ตัวก็ทำงานได้: /overview เริ่มงานใหม่ · /feature เพิ่มของ · /quick แก้จุกจิก

When does it stop and ask YOU?มันจะ "หยุดถามคุณ" เมื่อไหร่บ้าง

  • Before starting any new task — it briefs its understanding back; you confirm first (a wrong understanding wastes far more money than one question).ก่อนเริ่มงานใหม่ทุกครั้ง — มันเล่าความเข้าใจให้ฟังก่อน คุณยืนยันแล้วค่อยลงมือ (เข้าใจผิดแล้วทำ เสียเงินกว่าถาม 1 คำถามหลายเท่า)
  • Approvals — the plan, the feature doc, the price. No signature, no build.การอนุมัติ — แผนงาน ใบสั่งฟีเจอร์ ราคา — ไม่มีลายเซ็นคุณ = ไม่เริ่ม
  • Dangerous things — production deploys, deleting data, sending things out.ของอันตราย — ขึ้นระบบจริง ลบข้อมูล ส่งอะไรออกนอกบ้าน — หยุดรอคุณเสมอ
  • Final testing (UAT) + the merge — the last gate is always a person.ทดสอบรอบสุดท้าย (UAT) + กด merge — ด่านสุดท้ายเป็นของมนุษย์ตลอด

FAQคำถามที่เจอบ่อย

Do I need to know how to code?ไม่เขียนโค้ดเป็น ใช้ได้ไหม?›
No — your job is describing what you want, clicking through the test sheet, and approving. Reading code helps you review deeper, but isn't required.ได้ — หน้าที่คุณคืออธิบายสิ่งที่อยากได้ กดทดสอบตามใบที่มันทำให้ และตัดสินใจอนุมัติ อ่านโค้ดออกจะยิ่งตรวจได้ลึก แต่ไม่บังคับ
What does it cost?เสียเงินเท่าไหร่?›
The kit is free (MIT). You pay only your existing AI usage — and it's built frugal: loads only what's needed, compresses notes between phases, routes work to cheaper models where safe.ชุดนี้ฟรี (MIT) จ่ายแค่ค่า AI ตามแพ็กเกจที่ใช้อยู่แล้ว และมันถูกออกแบบมาประหยัด: โหลดเฉพาะที่ใช้ สรุปย่อระหว่างทาง ส่งงานให้โมเดลถูกกว่าเมื่อปลอดภัย
Which languages/frameworks?ใช้กับภาษา/เฟรมเวิร์กอะไรได้บ้าง?›
All of them. It pins a process, not a stack — you declare your stack once during /overview.ทุกอัน — มันคุม "วิธีทำงาน" ไม่ผูกกับภาษาไหน ประกาศ stack ของคุณครั้งเดียวตอน /overview
What if the AI makes mistakes?ถ้า AI ทำพลาดล่ะ?›
Tests are written before code so mistakes get caught; after 3 failed fix attempts it must stop and report; every problem is logged so it isn't repeated; and all work lives on a separate branch — nothing is real until you merge.มันเขียนเทสต์ก่อนโค้ดเสมอ พลาดจึงมีตัวจับ · แก้เกิน 3 ครั้งต้องหยุดรายงาน · ทุกปัญหาถูกจดกันซ้ำ · งานอยู่บน branch แยก — ของจริงไม่พังจนกว่าคุณ merge
Can it work while I sleep?อยากให้มันทำงานเองตอนกลางคืน / ตอนไม่อยู่?›
Yes — install with npx create-issflow --ci (GitHub: label an issue feature:approved and it runs) or --docker (a safe box on your machine: node scripts/feature-docker.js docs/features/<name>/FEATURE.md). Needs an Anthropic API key.ได้ — ติดตั้งด้วย npx create-issflow --ci (ผ่าน GitHub: ติดป้าย feature:approved ที่ issue แล้วมันทำเอง) หรือ --docker (รันในกล่องปลอดภัยบนเครื่องคุณ: node scripts/feature-docker.js docs/features/ชื่อ/FEATURE.md) ต้องมี API key ของ Anthropic
How do I uninstall?เลิกใช้ยังไง?›
Delete the .claude/ folder and AGENTS.md. Your code is untouched.ลบโฟลเดอร์ .claude/ กับไฟล์ AGENTS.md ทิ้ง — โค้ดของคุณไม่ถูกแตะ
